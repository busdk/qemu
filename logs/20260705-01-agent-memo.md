## Work Narrative

The prior hour attempted to symbolize the RISC-V artifact. Builds with `-g`/`--profiling-funcs` did not produce wasm `name` sections, and an `--emit-symbol-map` build was killed with exit 137. That means function index `1403` is not locally named yet. The practical code evidence from the parallel read-only scan pointed to `accel/tcg/translator.c`: `translator_ld()` used `qatomic_read` on the host pointer for instruction bytes after checking only the guest PC alignment. On Emscripten, that atomic load can become a trapping WebAssembly atomic if the host pointer is not naturally aligned.

I applied the narrow fix at that site. The atomic read path now requires both guest PC alignment and `QEMU_PTR_IS_ALIGNED(host, len)` for 2-, 4-, and 8-byte reads. If either side is not aligned, the code uses the existing `memcpy` fallback. This is intentionally small: it does not change the rest of translation, and it keeps the original atomic instruction-fetch behavior only where the host pointer is actually safe for Emscripten atomic lowering.
