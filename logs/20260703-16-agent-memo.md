## Work Narrative

The implementation added an opt-in `QEMU_WASM64_LIVE_TB_COVERAGE` path in
`tcg/wasm64.c`. The path scans live translated TB metadata until it finds a
generated-output TB whose TCI words are limited to a conservative
side-effect-free subset: integer ALU ops, moves, memory barriers, and terminal
`exit_tb`/`goto_tb`. It passes the actual C `INDEX_op_*` constants into the
Emscripten JavaScript side so the probe does not hard-code stale opcode
numbers. For a matching TB, the JavaScript builds a small `wasmjit_run` module
from the live TCI words, executes it against scratch register state, compares
status, terminal value, executed op count, and register checksum against a
JavaScript reference interpreter over the same words, then reports
`qemu-wasm64-runloop` event `live-tb-coverage`.

The proof deliberately records `guest_state_commit:false`: this slice proves
generated execution and coverage accounting against real live TB bytes, but it
does not let the generated body mutate the real guest. After the diagnostic
probe, the normal `tcg_tci_qemu_tb_exec` fallback still owns guest-visible
execution. That is the conservative bridge for R4d because older direct-memory
experiments were rejected as unsafe or slower, and this task explicitly
requires strict TCI fallback to remain the default.

Coverage accounting was also tightened. The earlier x86 one-TB metric helper
added the same guest-instruction count to both generated numerator and
denominator, which made a self-contained proof look like full coverage. The
new path records the denominator from the live TB execution stream and only
adds to the numerator after a generated live-TB proof succeeds. Unsupported
live generated-output shapes increment runtime fallback and unsupported-exit
diagnostics, while older generated-output-unavailable paths continue to report
first unsupported op shapes. The browser runner now exposes
`--wasm64-live-tb-coverage`, forwards it through the smoke page as
`QEMU_WASM64_LIVE_TB_COVERAGE=1`, and automatically enables it when
`--require-wasm64-tcg-coverage` is used so the R4d gate cannot request coverage
without enabling the probe.
