## Diagnosis

The live metadata association currently uses an 8192-entry direct-mapped
side table keyed by `tb_ptr >> 4`. Translation begin overwrites the selected
slot unconditionally, and live execution later accepts metadata only if the
slot still contains the exact same `tb_ptr`. That validation prevents false
association, but it also means ordinary cache-index collisions detach metadata
from still-live TBs. For the R4d live coverage probe, that turns valid
translation-time generated-output metadata into runtime misses before the
Chrome proof has a chance to report nonzero real-TB coverage. A bounded
open-addressing table should preserve the exact-pointer safety check while
making normal collisions deterministic instead of destructive.

## Change

I replaced the single-slot `tcg_wasm64_translate_entry()` helper with a small
bounded probe window. Translation insertion now reuses an exact pointer entry,
uses the first invalid entry in the probe window, or evicts the start slot only
after the window is saturated. Runtime lookup scans the same window and still
requires a valid metadata record whose table key and embedded `metadata.tb_ptr`
both match the live `tb_ptr`. This keeps the association fail-closed while
allowing nearby collisions to coexist.

The deterministic metadata test now checks the source contract for the new
helpers and includes a small model showing that two colliding TB pointers stay
independently associated, that a mismatched embedded metadata pointer is
rejected, and that saturated-window eviction remains deterministic.
